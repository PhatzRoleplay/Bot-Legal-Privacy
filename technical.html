What We Built

The bot began as a Node.js project on a Windows development PC. GitHub stores the source code, while an Oracle Cloud Ubuntu server runs the live production bot 24/7.

In simple terms

The Windows PC is where the bot is developed. GitHub is the source-code repository. Oracle Cloud is the computer that keeps the live bot running. Discord is where the bot operates.

Important: Your PC does not need to stay on for the bot to remain online.

24/7 Bot Service

Ubuntu uses systemd to keep the bot running automatically.

Service name 

phatzrp-bot

The service starts automatically when the server boots and restarts the bot if the Node.js process crashes.

Auto-start Auto-restart 24/7

Server Commands

Commands used when administering the live bot.

Check bot status 

sudo systemctl status phatzrp-bot --no-pager

Start bot 

sudo systemctl start phatzrp-bot

Stop bot 

sudo systemctl stop phatzrp-bot

Restart bot 

sudo systemctl restart phatzrp-bot

Updating the Bot

Develop locally, push to GitHub, then deploy the changes to Oracle.

1. Make changes locally

Edit and test the bot on the Windows development PC.

2. Push changes to GitHub

Commit and push the updated code to the private repository.

3. Pull the changes onto Oracle 

cd ~/phatzrp-discord-bot
git pull

4. Install dependencies when required 

npm install

5. Restart production 

sudo systemctl restart phatzrp-bot

Logs & Troubleshooting

Useful commands when something isn't working.

View recent logs 

sudo journalctl -u phatzrp-bot -n 50 --no-pager

Watch live logs 

sudo journalctl -u phatzrp-bot -f

Press Ctrl + C to stop viewing the live output.

If the bot is offline: Check the service status first, then inspect the recent journal logs for Node.js or configuration errors.

Security

Sensitive credentials should never be committed to the documentation repository or bot repository.

Discord Bot Token .env SSH Private Keys Database Passwords API Keys

Environment files

The production .env exists only on the Oracle server. The development copy exists on the PC. Neither should be stored in GitHub.

Never publish credentials. Keep bot tokens, SSH private keys and database credentials completely private.
